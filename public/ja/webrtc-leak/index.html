よくある質問

この WebRTC リークテストは何を調べますか？

ビデオ通話サイトと同じように、UDP で 4 つの STUN サーバー（Cloudflare、Google、Twilio、Xiaomi）にグローバル IP を問い合わせ、サイトが HTTPS で見ている出口と比べます。STUN にはローカル回線が、サイトにはプロキシが見えている場合、どのページからでも本当の IP が読み取れます。

WebRTC リークを直すには？

プロキシに UDP も中継させます。Clash、sing-box、Surge、Shadowrocket の TUN モードや拡張モード、または VPN のフルトンネルを使ってください。ブラウザで WebRTC を止める方法（uBlock Origin の「WebRTC によるローカル IP アドレスの漏洩を防止」、Firefox の media.peerconnection.enabled = false）もありますが、ビデオ通話が使えなくなることがあります。

「UDP 不通」と出ました。安全ですか？

WebRTC については安全です。STUN サーバーが応答しないので、ページはこの方法で IP を知ることができません。ビデオ通話は中継サーバー経由で使える場合があります。

VPN を使えば WebRTC リークは起きませんか？

すべての通信をトンネルする VPN なら起きません。ブラウザやシステムだけに設定したプロキシ（HTTP や SOCKS）は通常 TCP だけを中継するため、WebRTC の UDP は直接出ていきます。設定を変えたら再チェックしてください。

サイトによって見える IP が違うのはなぜ？

Clash、Surge、Shadowrocket、sing-box などのルール付きプロキシや VPN は宛先ごとに経路を選びます。中国のサイトは直接、AI サービスはあるサーバー、それ以外は別のサーバー、という具合です。1 つのサイトに聞くだけでは、そのサイトの経路しか分かりません。このページは数十の宛先に同時に問い合わせ、結果をネットワークごとにまとめます。

ChatGPT や Claude に見えている IP がなぜ分かる？

Cloudflare 配下のサイトは、自分のドメインの /cdn-cgi/trace で接続元のアドレスを返し、どのページからも読み取れるようにしています。ブラウザはいつもどおり、ルールが選んだ経路で chatgpt.com に接続し、chatgpt.com に見えたアドレスを読み取ります。

IPv6 漏れとは？

プロキシが IPv4 しか扱わず、回線に IPv6 もある場合、IPv6 の接続はプロキシを通らないことがあります。IPv6 専用のプローブで、IPv6 の通信が実際にどの出口から出ているかが分かります。

ローカルとプロキシはどう見分ける？

ネットワークの持ち主で判断します。クラウドやホスティング事業者（Amazon、Google Cloud、Alibaba、DigitalOcean など）のアドレスはプロキシ、最初の ISP のアドレスがあなたの回線です。住宅用プロキシや ISP 網上の VPN はこの方法では区別できません。

このサイトに何か送られますか？

いいえ。ブラウザが各プローブに直接接続します。このサイトは静的ファイルを配信するだけで、結果は届きません。スクリーンショットの前に「IP を隠す」を押してください。
